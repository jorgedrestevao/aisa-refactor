# aisa-round

## Usage

`/round [lens|--close]`

- No argument: in Discovery, runs the six lenses in the order defined in `library/kernel/phases.md`: `business → operations → user → data → governance → financial`. **The order is mandatory for a full round** (the `pre-lens-order-check` hook enforces it). In other phases → stop with: "/round is for Discovery; use /frame, /options, /decide for later phases."
- `[lens]`: a lens name (e.g., `data`) — runs **only that lens, on its own, with no prerequisite**: any lens, in any order, inside the round currently open (opening one if none is). The invocation carries `round mode: single` so the hook does not police it. A lens that already stamped the open round is not re-run silently (step 3.4).
- `--close`: closes the open round without running another lens — for a round deliberately run with a subset of the lenses. No lens runs; step 5 runs on the lenses that did.

## Execution steps

1. Read `_state.json` (resolve the engagement root as in `aisa-start`). Read `phase`, `round` and `round_in_progress`.
2. If `phase != discovery` → stop with the message above.
3. **Determine the round to run** — a round in progress is not a completed round (`library/kernel/phases.md` → *Rounds*). `round` holds the last **completed** round; `round_in_progress` holds the one an open `/round` is filling (empty or absent → none open).
   a. `round_in_progress` non-empty and ahead of `round` → the round to run **is** `round_in_progress`. A `round_in_progress` equal to or behind `round` is a leftover (phase transition, hand edit): ignore it and treat it as none open.
   b. Otherwise → increment `round` by one (`R-00`→`R-01`, `R-01`→`R-02`, ...). `aisa-start` seeds `R-00` (no round run yet), so the first `/round` runs `R-01`.
   c. **Persist the round record** (one atomic write, tmp -> rename) BEFORE invoking the first lens:
      - `round_in_progress` = the round to run. `round` does not move here. This is what lets `/round business` and then `/round operations` stamp the same round, what the `pre-lens-order-check` hook reads to know which round it is checking, and what survives a session that dies mid-round.
      - `round_lenses` = `{"ronda": "<R-NN>", "modo": "<full|single>", "lentes": [<the lenses THIS call will run>]}`. `modo: single` only for `/round <lens>` (one name in `lentes`); `modo: full` for `/round` with no argument and for *completar as que faltam* (3.4). **This record is the isolation signal the hook reads** — it is machine-written and scoped to the round and to the lens, so a leftover authorises nothing. Never hand-edit it; never write `single` for more than one lens.

      A `/round <lens>` that opens a fresh round writes both keys in the same write before the lens is invoked. Skipping this write means the hook polices the habitual order and an isolated lens is refused (what happened on `pricing-bunkers` R-03, 2026-09-09).
   d. `--close` → skip step 4 entirely and go to step 5 for the round in `round_in_progress` (none open → stop with: *"não há passagem em curso para fechar"*).

   The lenses stamp **this** round on their rows.
3.4. **Passagem guard** (only when a round is already open — 3a; runs BEFORE capture and context assembly so a *não correr* costs nothing). Read `engagement.lentes_ronda_aberta` from the motor (`python library/kernel/tools/dashboard.py --engagement <slug> --json <file>`; `corridas` / `em_falta`, header match, never a substring). Then:
   - `/round <lens>` and `<lens>` ∈ `corridas` → **`AskUserQuestion`** (business language; id/kernel term in the description): *«A perspectiva <X> já correu nesta passagem (ronda R-NN). Voltar a correr acrescenta linhas novas ao que já lá está.»* — options: *voltar a correr* / *não correr*. Never assume; a re-run is legitimate (new inputs, new answers) but never silent. *não correr* → stop with the `A seguir` line of step 6.
   - `/round` with no argument and `corridas` non-empty → **`AskUserQuestion`**: *«Há uma passagem a meio (ronda R-NN): já correram <X, Y>; faltam <Z…>.»* — options: *completar as que faltam* (runs only `em_falta`, in the habitual order, inside the open round) / *fechar esta e abrir nova* (step 5 closes the open round on what ran, then a fresh full round opens — 3b). Never run a lens twice in the same passagem without the user saying so.
   - `/round <lens>` and `corridas` is empty or does not contain `<lens>` → proceed. No prerequisite check: the lens runs alone.
3.5. **Capture freshness check**: for every capture-supported file in `inputs/` — `.xlsx`/`.xlsm` (structured tier) and `.docx`/`.pdf`/`.vtt` (capture-lite) — compare its SHA-256 with `identity.sha256` in `_capture/<file>.extraction.json`; both tiers write that key, so one rule covers both, and formats outside the tiers are never stale. Missing artefact, mismatched hash, or missing `_capture/evidence-index.md` → invoke the `aisa-capture` skill for the stale/missing file(s) BEFORE any lens runs (both extractors self-cache on SHA-256, so a fresh file costs one hash check). Comparison is hash/status only — never a semantic diff of old vs new content. Capture failure is soft: warn and name the file. What is never acceptable is a lens reasoning over normalized evidence whose source has since changed without being told — name any source left stale in the invocation (step 3.6a).
3.6. **Assemble the round context** (once per round, before the first lens). Pure bookkeeping: the orchestrator resolves paths and one manifest key. It does not decide what any of it means.
   a. **Shared evidence** — `<engagement>/_capture/evidence-index.md`. Present → carry its path. Absent (no `_capture/`, or capture could not run) → carry the explicit line *"no `_capture/evidence-index.md` — raw `inputs/` is the evidence surface"*; never let a lens assume a shared capture exists. Name likewise any source left stale by 3.5 or reported `failed`/`skipped`. Do **not** rank, assign, summarize or bundle sources, and do not build a per-lens evidence view: the index is a source map; which of it matters is the lens's judgement.
   b. **Pack attention cues** — read `_state.json.pack`, resolve `library/packs/<pack>/pack.yaml` → `lenses_config.<lens>.extra_signals` for the lenses about to run, once per round. Missing `pack` key, missing `lenses_config.<lens>`, missing `extra_signals`, or an empty list → inject nothing for that lens and continue: cues are optional enrichment and a lens works on its universal perspective without them. A `pack.yaml` that does not parse is a visible failure — report it and stop, as `aisa-start` step 3 does for a missing manifest (no new validation machinery). Pass the configured tokens through **verbatim**: no scoring, no ranking, no filtering, no reordering, no rewriting into questions, no coverage bookkeeping.
   c. **Next free SU ids** — scan `shared-understanding.md` for the highest id per prefix (`C-`, `A-`, `U-`, `X-`, `R-`; `library/kernel/states.md` → id prefixes) and compute the next free id per section. Lenses no longer carry this bookkeeping. **Recompute this scan immediately before EACH lens**, not once for the round: the lenses run in sequence and every one of them writes rows, so a set computed before the first lens hands the same `C-nnn` to the second. Two rows under one id make a citation ambiguous, and the motor cannot repair it — it reports `id duplicado` and keeps the first (F01, `docs/ADVERSARIAL_REVIEW_2026-09-08.md`). The scan costs one read of the SU per lens.
   d. **Enquadramento** — `<engagement>/enquadramento.md` (written by `aisa-start` step 9b). Present with invariants → carry its path and the list of `M-n` ids (ids only, never the text). Present but *"não declarado"*, or absent (pre-P-0 engagement) → carry the explicit line *"no enquadramento — the owner has not declared the business mechanism; `Unknown` rows must declare their divergence in the to-be instead of citing an `M-n`"*. The orchestrator never writes or infers an `M-n`.
4. For each lens to run (the full Discovery order, the `em_falta` subset chosen in 3.4, or just the named lens):
   a. If `.claude/skills/lens-<name>/SKILL.md` does not exist → skip it and note "lens `<name>` not installed". (All 6 Discovery lenses ship with aisa; this guard only matters for trimmed or customized installs.)
   b. Otherwise invoke the lens skill (e.g., `Skill: lens-business`) in **inline mode**, carrying this round context — the smallest set the lens needs, as pointers rather than contents:
      ```
      Round: <R-NN> · engagement `<slug>` · engagement root `<engagement>` · round mode: <full|single>   (echo of `round_lenses.modo`; the hook's authority is the state written in 3c, this line is only a fallback)
      Shared Understanding: `<engagement>/shared-understanding.md` — next free ids: C-NNN · A-NNN · U-NNN · X-NNN · R-NNN
      Request context: `<engagement>/context.json` · funding gate: `funding_gate` = <true|false> (absent → true) — read verbatim from `context.json`; the financial lens and `cfo-lens` condition their mandate on it (`lens-financial` → *Signal catalog*)
      Enquadramento: `<engagement>/enquadramento.md` — invariants M-1..M-n declared by the process owner (their hypothesis, `Confirmed` in ronda R-00; `/frame` confirms or corrects them). Every `Unknown` you write carries the three declarations of *Admission of a question* — the `M-n` its answer serves, ≥ 2 possible answers, and which of the eight technical axes moves with each — see your Hard rules. Citing an `M-n` does not waive the axis. (or the "no enquadramento" line from step 3.6d)
      Prior lens outputs this round: `<engagement>/lens-outputs/<lens>.md`, … (or "none — first lens of the round"; in single mode list whatever `corridas` holds — the habitual order is not assumed)
      Shared evidence: `<engagement>/_capture/evidence-index.md` — this engagement's source map (source · format · normalized evidence · status · cite as). Raw sources stay at `<engagement>/inputs/`, are always openable, and are authoritative on conflict. Read what bears on your perspective; nobody has decided that for you.
      Memory (optional): `.claude/agent-memory/_universal/<persona>/*.md` (incl. `diary.md` — cite a prior pattern by domain, never by client name) · `.claude/agent-memory/_tenant/<tenant>/<persona>/*.md`
      Pack attention cues (`<pack>`): <token>, <token>, … — cues, not a checklist. Follow only what is material to this engagement; an uncovered cue is not a gap and never becomes an `Unknown`.
      Comprehension survival: `<engagement>/_capture/process-model.md` §4 is the process synopsis (cross-source; lines marked OBSERVED / INFERRED / HYPOTHESIS / UNKNOWN, material lines labelled in backticks) and §6 the PM-U interrogation list. Within your perspective, every material synopsis line and every PM-U row you touch gets exactly ONE disposition in your `Open evidence` block — `MAP <SU id>` (already a row) · `ADOPT → <new id>` (row you created) · `DISMISS — <reason>` (not material for downstream decision reasoning). Markers are not states: OBSERVED → Confirmed only with the evidence; INFERRED → Assumed with basis; HYPOTHESIS → the Unknown that would settle it, or leave it in the synopsis; UNKNOWN → Unknown. A Critical PM-U may remain Unknown but never disappears silently. Disposition ≠ resolution.
      ```
      Omit the cue line entirely when step 3.6b resolved nothing (and say nothing in its place). Omit the comprehension-survival line when `_capture/process-model.md` does not exist. `<persona>` comes from the lens→persona map in *Notes*.
      **Do not dump.** No evidence bodies, no `pack.yaml`, no `question-bank.md`, no domain-knowledge files, no full prior-lens prose in the invocation — pointers only; the lens opens what it needs. The lens is told where things are, never what to conclude, which evidence matters, which cue is relevant, or which state a finding should get.
      > **MUST:** Call the `Skill` tool with `skill="lens-{name}"` for each lens. Never read `SKILL.md` files directly and run the analysis yourself — doing so bypasses the `pre-lens-order-check` hook that enforces the order of a full round. The hook reads `_state.json.round_lenses` (written in 3c), so the order of a full round is enforced and an isolated lens is not. Fail-closed: with no record for this round and this lens, the order is policed.
   c. Confirm the lens wrote rows to the SU and a paragraph to `lens-outputs/<lens>.md`. Check that no id it wrote already existed before it ran (the scan of 3.6c is what makes this a check and not a hope); a collision is fixed **now**, by renaming the new row (`was <id>` on the renamed one), never left for the reader.
5. After the lenses of this call finish (with `--close`, straight to here):
   a. **Close test, then persist.** Re-read `engagement.lentes_ronda_aberta` from the motor after the lenses wrote. The round closes when `em_falta` is empty (all six stamped this round — in one call or across several `/round <lens>` calls, in any order) or on `--close`. *Never* on "the lens just run is `financial`": with isolated lenses `financial` may be the first one to run.
      - Closes → one atomic write (tmp → rename) setting `round` = the round just run, `round_in_progress` = `""` **and** `round_lenses` = `{}` (the record dies with the round it names). `round` therefore always holds the most recent **completed** round = the engagement's current round.
      - Does not close → `round` does **not** move and `round_in_progress` keeps the open round. Name, in step 6, the perspectives still missing in this passagem.
   b. Update the SU header `Última actualização` timestamp.
   c. Append a summary to `council-log.md` naming the lenses **this call** ran and whether the round closed or stays open.
   d. **On close only** (one episode per passagem, never one per lens) — append one narrative episode to `<engagement>/story.md` (`## Episódio <N> — <data> — ronda de Discovery (o que se descobriu, o que ficou por saber)`): 4-8 frases na voz do sponsor, sem jargão de kernel, máx. 2 ids citados. Create the file with `# Story — <slug>` if missing (pre-v2.3 engagements).
   e. **Disposition bookkeeping** (only when `_capture/process-model.md` exists; string presence, never judgement): list every **Critical** `PM-U` id and every backtick-labelled material synopsis line of §4 that no `Open evidence` block — this round or an earlier one — names with `MAP` / `ADOPT` / `DISMISS`. Report them as `undisposed`. Never dispose of one yourself and never promote a PM-U to an SU row: that is a lens's judgement, taken in the next `/round <lens>`. `/frame`'s soft gate reads the same list.
   f. **Round arbiter — admission** (presence of declarations, never judgement). Rule and bounds: `library/kernel/states.md` → *Admission of a question*. Deterministic support: `python library/kernel/tools/dashboard.py --engagement <slug> --json <file>` → `arbiter.sem_declaracao` / `sem_eixo` / `sem_citacao_m` / `decisivo_sem_referente`, filtered to `ronda = R-NN`. **Run the motor first; then read every row it names.** Its lists are presence checks with known false positives — a row that declares in words the regex does not know is a false positive, and the judgement is yours (`falsos_negativos` says the same in reverse). `sem_coluna_swing` / `sem_eixo_sem_coluna` count pre-v2.3 rows that *cannot* declare anything: never act on those.

      Per `Unknown` created this round, three declarations, **all three**: (i) cites an existing `M-n` **or** carries the marker `TO-BE DIVERGENCE` with what the target must decide (either form, framing declared or not); (ii) `swing` names ≥ 2 answers; (iii) `swing` names which of the eight axes moves — `tecnologia` · `padrão arquitetural` · `componentes` · `modelo de dados` · `plano de imposição de permissões` · `esforço de alto nível` · `custo` · `risco técnico`. **An `M-n` does not waive (iii)** (P-26). Any missing → `cosmético`; `decisivo` with no named referent → `dimensionante`.

      **Two edits, in this order, on that row only:**
      1. class token at the start of `swing` → `cosmético` (or `dimensionante`); append ` — reclassificado P-26 (R-NN): <declaração em falta>`;
      2. **only if 1 fired**, and only if `criticidade` is above `Low`: → `Low`; append ` — criticidade baixada P-26 (R-NN): <a razão que a sustentava>`.

      One line per row in `council-log.md` naming both (`swing corrigido: U-nnn dimensionante → cosmético (sem eixo técnico) · criticidade Critical → Low`). **Never**: delete a row, rewrite the question, judge materiality, raise a `criticidade`, or touch a row whose `swing` was already `cosmético` before this pass. Which options a question touches is `/simulate`'s judgement, not yours (emenda F10).
      **The one materiality class that is the arbiter's** (P-21, the role rule — `library/kernel/states.md` → *Question economics*). A row whose question, or whose `swing`, names as its consequence **only** a person's identity, a signature, an approval, an acceptance, or a document proving a third party's position changes no requirement, no data shape and no effort. Reclassify it `cosmético`, append ` — reclassificado P-21 (R-NN): pergunta de pessoa ou de papel, sem divergência no to-be`, carry the `criticidade` down with it exactly as in the second effect above, log the line in `council-log.md`, and say in the round output that the question must be reformulated by **role, operation and enforcement plane** or dropped. This is a **class** test, not a case-by-case opinion, and it is the only materiality judgement the arbiter makes.
      **Second reading — `Confirmed` created this round** (`library/kernel/states.md` → *Confirmed threshold*). For each new `C-` row ask three things: does the evidence carry a locator of the five classes; does the claim say more than that evidence says; and does the evidence **contradict** the claim? A direct extraction the lens made over the raw source counts only once it is **persisted in `_capture/`** and the evidence points at that file (states.md rule 1, fifth class) — a method declared in prose is not a locator. A missing locator is reported (`Confirmed sem locator: C-nnn`, one line in `council-log.md`; the deterministic hook will do the same). A claim above its evidence is **not a metadata edit**: it is a transition — new row `A-nnn was C-nnn`, basis = the locators, original marked ` — resolved → A-nnn`, one line in `council-log.md`. A claim the evidence **contradicts** is a transition as well, but the state does not drop when that evidence settles the right value: new row `C-nnn was C-nnn` with the corrected claim and the locator that fixes it (`states.md` → *Correction by evidence*). Without a locator that settles it, the row goes to `Assumed`. Never edit the claim in place. The arbiter reads only this round's rows, and only those it has not touched yet: a row whose `swing` already carries ` — reclassificado P-1` is skipped, as is a row already marked ` — resolved →`. With a round that spans several `/round <lens>` calls the same rows come back under the eye each time; reclassifying twice would stack markers and rewrite a class the first pass already fixed.
   g. **Convergence** (counts from the motor only — `python library/kernel/tools/dashboard.py --engagement <slug> --json <file>`, never by hand). Read, for the round just run: `Unknown` **criadas** this round (rows with `ronda = R-NN`), **fechadas** this round (rows marked `resolved →` whose resolution happened this round, any origin — `/answer`, transition, arbiter), **abertas** total and **Critical abertas**. `criadas > fechadas` → label the round `sem convergência`. Visible, never blocking: no gate, no new state. All four come from `round_delta`: the entry of `round_delta.por_ronda` whose `ronda` is the round just run gives `criadas`, `fechadas` and `sem_convergencia`; `round_delta.abertas` and `round_delta.critical_abertas` are the engagement's current totals. When `round_delta.indeterminadas` is non-empty, say how many closures the motor could not date — never estimate them into a round. With the round still open (5a did not close it) the numbers are this passagem **so far** — say so; they are not a closed round's balance.
6. Output (business language — `CLAUDE.md` → *Duas línguas*; kernel labels and ids only between parentheses; the numbers are 5g's, never recounted):
   ```user-output
   Passagem <N> <concluída | a meio> (ronda R-NN) — perspectivas nesta chamada: <negócio, operações, utilizador, dados, controlo, custo | a que foi pedida>.
   <só quando ficou a meio> Faltam nesta passagem: <utilizador, dados, controlo, custo> (lentes_ronda_aberta.em_falta, em palavras).
   <só em modo isolado, quando a de negócio ainda não correu nesta passagem> A perspectiva <X> correu sem a leitura de negócio desta passagem — apoia-se no que o dono declarou ao arrancar (enquadramento) e nas passagens anteriores.
   Perguntas que os ficheiros levantaram e em que ninguém ainda olhou: <nenhuma | <n> — <descrição curta> (PM-U-NNN, grave) …>.
   Perguntas reclassificadas por não dizerem o que muda: <nenhuma | <n> — <pergunta curta> (U-nnn: passou a «não muda nada», e deixou de contar como grave) …>.
   Nesta passagem: <n> perguntas novas · <n> fechadas · <n> em aberto no total (<c> graves) <· abrimos mais do que fechámos>.
   A seguir: <passo humano, se houver — ex.: reunião com o dono para as perguntas graves> → <passagem a meio: `/round <perspectiva seguinte>` para continuar, ou `/round --close` para a dar por fechada> <passagem concluída: `/status` para ver o que falta, ou `/round` para outra passagem>.
   ```

## Notes

- `/round` with no argument starts a NEW round and closes it in the same call (or, with a passagem open, asks whether to complete it — 3.7). `/round <lens>` runs inside the round already open, or opens one; the counter only moves forward, and it moves when the round **closes** (step 5a), not when a lens writes. Lenses append and never rewrite prior rows, so a re-run never corrupts — but it does add a second `## R-NN — <lens>` section and a second batch of rows, which is why 3.7 asks before re-running a lens in the same passagem.
- **A round in progress is not a completed round.** `round_in_progress` is what the `pre-lens-order-check` hook reads to know which round it is checking; without it a single-lens `/round business` closed R-01 and the next `/round operations` looked for R-02 output that could not exist (P-R6, `docs/ADVERSARIAL_REVIEW_2026-09-08.md`). `/frame` reads `round`, so a passagem left open never counts as a completed round at the phase gate — close it with `/round --close` first.
- **Order: mandatory for the full round, free for a single lens.** The habitual order exists for predictability and debuggability (see `library/kernel/orchestration.md`), and `/round` with no argument keeps it. `/round <lens>` is the escape hatch: any lens, alone, no prerequisite — the hook sees `round mode: single` and stands aside. A lens run alone before `business` is not blind: the owner's `M-n` (R-00) and earlier passagens are already in the SU; the output says so (step 6) and moves on.
- **Lens → persona** (for the memory pointer only): business → `business-analyst` · operations → `operations-lead` · user → `user-advocate` · data → `data-steward` · governance → `compliance-officer` · financial → `cfo-lens`.
- **Discovery cues stay in Discovery.** This loop runs the six Discovery lenses only; `lens-technology` is never invoked here and never receives Discovery `extra_signals`. It activates in Options, where it resolves the pack itself — pull-based (`library/kernel/orchestration.md` → *Pack context*).
- **The pack's question bank is not lens context.** It is not resolved here and never enters a lens invocation. Its single consumer is `aisa-status` step 6, where questions are formulated after reasoning has exposed what matters.
- **Disposition is projection, not resolution.** `MAP` / `ADOPT` / `DISMISS` make material process semantics visible in the SU before compression (`library/kernel/orchestration.md` → *Comprehension survival*). An adopted Critical PM-U may stay `Unknown` for the whole engagement; what is forbidden is the silent fourth outcome. The orchestrator checks presence of a disposition (step 5e); which disposition, and whether a line is material, is the lens's call.
